# 収入可視化アプリ UI/UX 改善案

## 1. 目的と位置づけ

本書は、現在の画面と [`要件定義書.md`](./要件定義書.md)、[`設計書.md`](./設計書.md) を確認し、デザイナーの視点で利用者が収入の推移をより早く理解し、安心して比較できるようにする改善案をまとめたものである。

ここに記載する内容は提案であり、決定済みの要件や実装仕様を変更するものではない。採用する項目は、実装前に必要に応じて要件・設計へ反映する。

## 2. 現状の画面

- ヘッダーにアプリ名とテーマ切り替えボタンがある。
- メイン領域に「収入推移」の見出しと、税引後・万円表示の説明がある。
- 給与、配当金、その他を積み上げた年別棒グラフがあり、各年の合計と凡例を表示する。
- グラフの下に同じデータを示す表がある。
- 狭い画面ではグラフと表を横スクロールして閲覧する。
- 読み込みやCSV検証に失敗した場合、エラーを表示する。

## 3. デザイン上の目標

1. ページを開いてすぐ、対象期間・金額の前提・収入の概況が分かる。
2. 収入全体の変化と、内訳ごとの変化を無理なく比較できる。
3. スマートフォン、キーボード、スクリーンリーダーでも同じ情報へ到達できる。
4. 色やグラフの装飾だけに頼らず、正確な値と意味を理解できる。
5. サンプルデータであることや金額の前提を誤解なく伝える。

## 4. 改善提案

### P1: 画面上部に期間と収入の概要を追加する

**現状の課題**

見出しと説明の後にグラフが続くため、利用者は年ごとの合計や内訳をグラフから読み取る必要がある。期間も説明文だけでは明示されていない。

**提案**

- 見出しの近くに対象期間（例: 2016〜2025年）と「税引後」「単位: 万円」を短いラベルで表示する。
- グラフより前に小さなサマリーカードを設け、「最新年の合計」「前年からの増減」「対象期間の合計」などを要約する。
- サマリー値には対象年や比較対象を併記する。年の欠落、比較不能、前年が0円の場合は増減率を無理に計算せず、適切な説明または非表示とする。
- 既存の年別データを集計して表示し、グラフと矛盾する独自データを持たない。

**期待効果**

利用者が詳細なグラフ読解に入る前に、収入の規模と主な変化を把握できる。

### P1: グラフの見方と比較の手掛かりを強化する

**現状の課題**

積み上げ棒は合計の推移には向く一方、各系列の年ごとの変化は棒の高さやツールチップから読み取る必要がある。合計ラベルが小さい画面で密集すると比較しにくくなる可能性もある。

**提案**

- グラフ見出しの近くに、積み上げ棒の意味と「棒の高さは合計、色分けは収入区分」を簡潔に案内する。
- 区分色とテキストの対応を凡例・ツールチップ・表で一貫させる。色覚特性やダークモードでも判別しやすいコントラストを確認する。
- ツールチップには年、各区分、合計を明確な順序で表示し、金額と単位を常に併記する。
- 合計ラベルが重なる幅では表示密度を調整する。値そのものはツールチップと表で確認できる状態を保つ。
- グラフの近くに、全データを含む表へ移動するリンクを置く案を検討する。

**期待効果**

グラフの読み方を学ぶ負担を減らし、合計と内訳のどちらも誤読しにくくする。

### P1: スマートフォンの横スクロールを分かりやすくする

**現状の課題**

狭い画面ではグラフと表が横スクロールになるが、スクロールできることや現在の閲覧位置が視覚的に伝わりにくい場合がある。

**提案**

- スクロール領域の端に影やフェードを付け、続きがあることを示す。
- 初回表示時に短い補助文（例:「左右にスクロールして全期間を確認できます」）を表示する。操作後に隠す場合も、支援技術に必要な説明を残す。
- 表では年の列を固定する案を検討し、横移動中も各金額の対象年が分かるようにする。
- タッチ操作とキーボード操作の両方で横移動でき、フォーカス位置が見失われないことを確認する。
- 小画面で文字や棒を極端に縮小せず、必要な横幅を維持する。

**期待効果**

全10年の表示を保ったまま、スマートフォンでも閲覧範囲と操作方法を発見しやすくする。

### P2: 表を比較しやすく整える

**現状の課題**

表は正確な値を提供しているが、行を追う際に年と金額の対応や合計列を目で追い続ける必要がある。

**提案**

- 数値列の桁を揃え、合計列を背景・太字・余白などで控えめに強調する。
- 行ホバーやキーボードフォーカス時に行全体を識別しやすくする。色だけでなく輪郭や背景差も使う。
- 年の列を固定する場合は、固定列と他列の境界が明確になるようにする。
- 表の単位と税引後であることをcaptionまたは近くの説明で明示し、スクリーンリーダーでも理解できるようにする。

**期待効果**

隣接する年や項目の値を比較しやすくし、グラフを使わない利用者にも読みやすいデータ提示にする。

### P2: テーマ切り替えとダークモードの分かりやすさを上げる

**現状の課題**

テーマ切り替えはアイコンが中心で、現在の状態や押した後の動作が画面上で判断しづらい。グラフの軸やグリッドの色もテーマに応じた見やすさの検証が必要である。

**提案**

- ボタンに「ダークモードに切り替え」「ライトモードに切り替え」など、現在の状態と操作内容が分かるアクセシブルな名前を付ける。
- ボタンの見た目にもテーマ名または明確なラベルを補い、アイコン単独に依存しない案を検討する。
- グラフの軸、目盛り、グリッド、ツールチップ、系列色をライト・ダーク両テーマで確認し、十分なコントラストを確保する。

**期待効果**

テーマ操作の予測可能性と、両テーマでのデータ可読性を高める。

### P2: サンプルデータとエラー状態の説明を整える

**現状の課題**

画面の短い説明だけでは、サンプル値の性質や「その他」の対象範囲が分かりにくい。エラー状態ではデータを表示しないことは分かるが、原因や次に何をすべきかが限定的である。

**提案**

- 画面の説明または補足リンクで、データがサンプルであること、「その他」に含まれる収入の例、税引後金額であることを簡潔に示す。
- CSV検証エラーでは既存の行・列情報を保ち、どのデータを確認すればよいか理解できる文面にする。
- 読み込みエラーでは、利用者にできる操作がない場合はその旨を明記し、技術的な内部情報は表示しない。
- エラー表示にもページ見出しと通常画面と同等の余白・コントラストを適用する。

**期待効果**

金額の前提を誤解しにくくし、データが表示されないときの不安や混乱を軽減する。

## 5. 優先順位の考え方

| 優先度 | 提案 | 主な理由 |
| --- | --- | --- |
| P1 | 期間・収入概要、グラフの読み方、モバイル横スクロール案内 | 画面の第一印象と主要タスクである推移の理解に直接影響する。 |
| P2 | 表の比較性、テーマ操作、サンプル・エラー説明 | 正確な読み取り、アクセシビリティ、安心感を段階的に改善する。 |

優先度はデザイン上の初期案であり、利用状況や実装コストを確認して調整する。

## 6. 採用時に確認すること

- 既存要件の「全期間を表示」「合計額を表示」「グラフと同じ値を表で提供」を維持する。
- サマリーカードの追加で、同じ情報の重複や過度な装飾が生じないか確認する。
- 集計値・増減値は既存データから一貫して算出し、比較できない条件の表示を定義する。
- ライト・ダークモード、スマートフォン幅、キーボード操作、スクリーンリーダーで確認する。
- 改善案を正式採用する場合は、必要な仕様を要件定義書・設計書へ反映してから実装する。
